# D'Acqua Dolce RAG Integration

## Current request ordering

The production chat orchestration order is:

    user request
        |
        v
    deterministic policy
        |
        +-- handled ----------> policy response
        |
        v
    authoritative business-data router
        |
        +-- price ------------> D'Acqua backend
        |
        +-- availability -----> D'Acqua backend
        |
        v
    curated knowledge retrieval
        |
        v
    inference provider

This ordering is intentional.

Retrieval cannot override deterministic policy and cannot replace authoritative
runtime business data.

## Retrieval behavior

The current retriever is the deterministic lexical baseline.

The retriever searches only the curated corpus and returns up to three
documents.

Retrieved material is inserted into inference as a separate system/reference
message after any caller-supplied leading system messages and before the
conversation turns.

The inference provider remains unaware of how retrieval is implemented.

## Response metadata

Model-generated responses expose:

    knowledge_document_ids

This identifies which curated documents were supplied to the model.

A RAG answer continues to use:

    source = "model"

because the final natural-language response is generated by the inference
provider.

Policy and business-tool responses do not invoke retrieval.

## Dynamic business facts

RAG must not provide current:

- pricing
- inventory
- scheduling
- quote state
- account state
- order state
- customer data

Those remain authoritative-tool concerns.

## Security boundary

Retrieved text is framed as reference data, not executable instructions.

The model is explicitly told not to treat instructions inside retrieved
material as higher-priority instructions.

Only curated, approved knowledge should enter the production corpus.

## Evaluation

The original eight raw-model prompts are rerun through the integrated pipeline.

The resulting report compares:

    raw model response
        vs.
    policy/tool/RAG/model response

No automatic content-quality score is assigned. Responses remain subject to
human review against the original evaluation criteria.

This comparison should be completed before adding embeddings or pgvector.
